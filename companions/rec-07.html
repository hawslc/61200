The Master Theorem is a contest between the root and the leaves

You’ve matched recurrences to cases at the board. Here’s the picture that makes the three cases obvious, the places where the theorem goes silent, and a pile of examples to check yourself against.

1

Each case is about which end of the tree is heavier

Lecture’s proof sketch is the whole intuition, so start there. Unroll T(n) = a · T(⌊n/b⌋) + f(n) and you get the recursion tree: 1 node at n, a nodes at n/b, a² nodes at n/b², and in general ai nodes at n/bi, down to depth k = logb n.

A node of size m does f(m) work itself, then hands the rest to its a children. So level i does ai f(n/bi) work in total, and T(n) adds up the levels:

T(n) ≈ f(n) + a f(n/b) + a² f(n/b²) + ⋯ + ak f(n/bk)

Going down one level, two things happen at once: the number of nodes multiplies by a, and each node’s problem shrinks by a factor of b. Which effect wins decides the case.

Try it

Pick a recurrence. See which level of the tree does the work.

Three shapes, three cases. Bars growing toward the bottom: the leaves win, and that’s case 1. Bars all equal: you pay one level’s work once per level, which is where the extra log n comes from — case 2. Bars shrinking: the root wins — case 3.

Where nlogb a comes from

It’s the bottom row. The tree has depth k = logb n, so the bottom row has ak = alogb n = nlogb a nodes, each doing a constant amount of work. So nlogb a is what the leaves cost, and f(n) is what the root costs. Every case compares the root’s work to the leaves’ work.

Why alogb n = nlogb a
Write a = blogb a and n = blogb n. Then both sides equal b(logb a)(logb n). For 4T(⌊n/2⌋) + n, 4log2 n = nlog2 4 = n².
Why growing / flat / shrinking lines up with the theorem’s comparison

Take f(n) = nd. Level i does ai (n/bi)d = nd · (a/bd)i — a geometric sum with ratio a/bd, straight out of Lec 05. Ratio above 1: the last term dominates. Below 1: the first term dominates. Exactly 1: all k + 1 terms are equal.

And a/bd > 1 exactly when d < logb a, i.e. when f(n) is polynomially smaller than nlogb a. The theorem’s comparison and the ratio are the same test, asked two ways.

You’ve already done the flat case by hand. Plug and Chug on Mergesort produced (n − 1) + (n − 2) + (n − 4) + ⋯: one term per level, each just under n, for log₂ n levels. Total: n log₂ n − n + 1.

2

Then it’s one comparison: f(n) against nlogb a

The theorem turns the picture into a checklist. Here it is as Lecture 07 states it.

Theorem 1 (Master Theorem) · Lec 07

Let a ≥ 1 and b > 1 be constants, let f(n) be a function, and let T(n) be defined on the nonnegative integers by the recurrence

T(n) = a · T(⌊n/b⌋) + f(n).

Then T(n) has the following asymptotic bounds:

  1. 1.
    If f(n) ∈ O(n(logb a)−ϵ) for some constant ϵ > 0, then T(n) ∈ Θ(nlogb a).
    leaves win
  2. 2.
    If f(n) ∈ Θ(nlogb a), then T(n) ∈ Θ(nlogb a log n).
    every level ties
  3. 3.
    If f(n) ∈ Ω(n(logb a)+ϵ) for some constant ϵ > 0, and if a f(⌊n/b⌋) ≤ c f(n) for some constant c < 1 and all sufficiently large n, then T(n) ∈ Θ(f(n)).
    root wins

This theorem is also true if we replace ⌊n/b⌋ with ⌈n/b⌉ everywhere.

Your notes write f(n) = O(…). Why ∈ here?
Lecture 07 prints the theorem with =. Lecture 06 reads that = as set membership — it calls the = form “ew, but most common” and prefers ∈ — and Lecture 07’s own worked examples switch to ∈. Same theorem, same meaning.

The recipe

  1. Match the form. Read off a, b and f(n). Check a ≥ 1, b > 1, and that the recursive call is on ⌊n/b⌋ or ⌈n/b⌉.
  2. Compute nlogb a, the cost of the bottom row.
  3. Compare f(n) with it. Smaller by a factor of nϵ: case 1. Same Θ: case 2. Bigger by a factor of nϵ: case 3, once you’ve checked its second condition.
  4. Read off the Θ. If none of the three fits, the theorem says nothing at all.

3

The theorem has gaps, and you should know where they are

Lecture is upfront about it: the Master Theorem doesn’t cover every recurrence. There are two ways to fall out.

“Bigger” has to mean bigger by nϵ

Lecture’s example is T(n) = 2T(n/2) + n log n. Here nlogb a = n, and n log n is bigger than n. Case 3, then? Case 3 asks for f(n) ∈ Ω(n1+ϵ) for some constant ϵ > 0: bigger by a polynomial factor. Divide through by n and that’s log n ∈ Ω(nϵ). Try to find an ϵ that works.

Try it

Shrink ϵ. Find where nϵ overtakes log₂ n.

log₂ nnϵlog₂ n ahead
No ϵ works. Every nϵ overtakes log n eventually, so log n ∉ Ω(nϵ) and case 3 is out. Case 2 is out too: n log n ∉ Θ(n), since the ratio log n is unbounded. The theorem is silent. Lecture’s advice: a more careful recursion-tree analysis, or induction.
Where the careful analysis starts
Use the tree from §1. Level i has 2i nodes of size n/2i, each doing (n/2i) log₂(n/2i), so the whole level does n(log₂ n − i). The levels do shrink, but by subtracting n each time instead of by a constant factor, so this is not a geometric sum. Adding it up is a Lec 05 exercise.
The same gap, from below
T(n) = 2T(⌊n/2⌋) + n / log n. Now f(n) is smaller than n, but again only by a log factor. Case 2 needs Θ(n); case 1 needs O(n1−ϵ). Neither holds.

The recurrence has to divide

Towers of Hanoi: T(n) = 2T(n − 1) + 1. Two recursive calls plus constant work looks like the right shape, but n − 1 isn’t ⌊n/b⌋ for any b > 1. Compare the trees at the legend’s 64 discs:

✓ Divide · Mergesort
T(n) = 2T(⌈n/2⌉) + n − 1
At n = 64 the size halves each level: depth log₂ 64 = 6, and the bottom row has 2⁶ = 64 leaves. Log depth, polynomially many nodes.
✗ Subtract · Hanoi
T(n) = 2T(n − 1) + 1
At n = 64 the size drops by 1 each level: depth 63, and the bottom row has 2⁶³ nodes. T(64) = 2⁶⁴ − 1 moves, about half a trillion years at one per second.
Linear depth means exponentially many nodes, which is why Hanoi’s answer is exponential. Lecture solves it with Guess and Check: T(n) = 2n − 1. Selection Sort’s T(n) = n − 1 + T(n − 1) falls out the same way; summing directly gives (n − 1)n/2.
And case 3’s second condition?

a f(⌊n/b⌋) ≤ c f(n) with c < 1 says the level below the root does at most a c fraction of the root’s work — the shrinking-bars shape from §1, demanded outright.

For f(n) = nd it holds automatically: a⌊n/b⌋d ≤ (a/bd) nd, and a/bd < 1 is exactly what case 3’s first condition gives you. It is still part of the check, so write it down.

Check
Lecture’s T(n) = 2T(n/2) + n log n falls under which case?

The short version

  1. Draw the tree before you pick a case. Level i does ai f(n/bi) work, and the case is just which end of the tree is heavier.
  2. Compare f(n) with nlogb a. That’s root against leaves. Leaves heavier: Θ(nlogb a). A tie: Θ(nlogb a log n), one log for the number of levels. Root heavier: Θ(f(n)).
  3. Heavier means heavier by a factor of nϵ. A log factor isn’t enough, which is why 2T(n/2) + n log n fits no case.
  4. In case 3, check the second condition. a f(⌊n/b⌋) ≤ c f(n) for some c < 1. It’s automatic for powers of n, but say so.
  5. Check the form first. T(n − 1) isn’t T(⌊n/b⌋). Hanoi and Selection Sort need other tools.
