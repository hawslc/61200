Swap in anything congruent — except where you can’t

Mod n, you can add, subtract, multiply and replace a base with anything congruent to it. Exponents and division have conditions. This page has a lot of small examples, so you get used to checking those conditions every time.

The recitation sheet’s list. a ≡n b means n | a − b, and nothing else. M4 and M5 are Lecture 09’s Theorem 6, and M6 and M7 follow by using it twice. Theorem 7 adds one more: if x ≡n y, then xk ≡n yk for every k ≥ 1.

The warning from the sheet: ak ≡n bk does not in general imply a ≡n b. It does when gcd(n, k) = 1 — for example, when n is prime and k isn’t a multiple of n. Nothing on the list lets you change an exponent either. Those two gaps are §2 and §3.
1

a ≡n b is a relation; a rem n is a number

a rem n is a function. It has exactly one value, always between 0 and n − 1, even when a is negative. a ≡n b is a statement that is true or false, and neither side has to be reduced. Lecture 09 avoids writing “mod” on its own because “a = b mod n” could mean either one.

Try it

Pick a modulus and any integer, including negative ones. Find which class it falls in.

Every integer is congruent to its own remainder, and to infinitely many other numbers. There are only n classes, and a rem n picks one standard representative from each. That gives you Theorem 5: a ≡n b iff (a rem n) = (b rem n). When a problem asks for a remainder, the last line of your answer has to be in the range 0 to n − 1. Anything else is a congruence.

True or false?

Fourteen statements. Some need a line of reasoning from the definition, not just arithmetic.

The modulus can move in one direction only. If x ≡12 5, then x ≡4 1, because anything 12 divides, 4 divides too (D2 from Lecture 08). The other direction fails: 1 ≡4 1, but 1 ≢12 5. Knowing x rem a big modulus tells you x rem each of its divisors, not the reverse.
2

Replace a base with anything congruent to it. Never replace an exponent that way.

Theorem 7 is about the base: x ≡n y gives xk ≡n yk. The exponent is a count of how many times you multiply, not a number mod n. Lecture’s counterexample: 1 ≡5 6, but 21 ≢5 26. The one exception is Fermat’s Little Theorem, which lets you reduce an exponent mod p − 1 (not mod p), and only when p is prime and a ≢p 0.

Look at the row of powers. It always repeats, and when it repeats is what lets you handle big exponents. For prime n it comes back to 1 by j = n − 1, which is Fermat. Sometimes it gets there sooner — 23 ≡7 1 — and you can use the earlier 1 too. When n = 10 or 12 the row repeats on its own schedule, and usually not after n steps.

Check two things before you cite Fermat: the modulus is prime, and the base isn’t a multiple of it. Problems 4 and 5 use a composite modulus, and §5 has a base that’s ≡ 0. Then reduce the exponent mod p − 1. Lecture puts it this way: we reduce mod n − 1 instead of mod n.
3

You can only divide by something that has an inverse

Mod n, “dividing by k” means multiplying by k−1, an integer with k · k−1 ≡n 1. Theorem 8 says it exists iff gcd(k, n) = 1. If it doesn’t exist, then multiplying by k loses information, and you can’t undo it.

When gcd = 1, the bottom row is the top row shuffled. Every remainder is hit exactly once, so every equation kx ≡n b has exactly one solution. That’s the shuffle in Lecture 09’s proof of Fermat (3, 6, 2, 5, 1, 4 mod 7). When gcd(k, n) = g > 1, only multiples of g get hit, each one g times. So you get no solutions or g of them, never exactly one.

Find the inverse with the Pulverizer

This is Recitation 09’s Problem 2. Run Lecture 08’s state machine on (n, k). The invariant x = ns + kt holds the whole way. If the final x is 1, then 1 = ns + kt, so kt ≡n 1, and t is an inverse of k. Take t rem n to get it into 0 … n − 1.

When the gcd isn’t 1, you can still divide the modulus along with everything else. 6x ≡9 3 means 9 | 6x − 3 = 3(2x − 1). By D4 from Lecture 08, that holds iff 3 | 2x − 1, i.e. 2x ≡3 1. That’s a legal step. Dividing by 3 and keeping the 9 is not.
4

A huge exponent takes about log₂ e steps, not e

Repeated squaring is the base-substitution rule used over and over. Square and reduce, square and reduce, so you have a1, a2, a4, a8, … mod n. Then multiply together the ones matching the 1-bits of e. Every number you multiply is less than n. RSA uses this in Lecture 10.

Try it

Compute rem(ae, n), and count the steps.

Try e = 1000000000000. That’s 40 binary digits, so at most 39 squarings and 39 multiplications. The step-by-step method from Problem 3(a) would take 1012 − 1 steps. If n is prime, Fermat can shrink e first, but repeated squaring works for any n. RSA needs that, because its n = pq isn’t prime.
5

Where’s the error? A right answer doesn’t make the argument right

Each item is a short argument of the kind you might write on an exam. Mark each one Valid or Bogus. An argument is valid only if every step is licensed by M1–M7, Theorem 7, an inverse that actually exists, or Fermat with its hypotheses checked. Some of the bogus arguments still get the right number.

Bogus with a correct final answer is still bogus. Item 11 gets 1, and 1 is correct. But reducing the exponent mod 10 isn’t allowed, and the same method gives a wrong answer for 355. Graders check each step, not just the final number.

The short version

  1. Write ≡n for congruence and rem for the remainder. A remainder is one number in 0 … n − 1, never negative. A congruence doesn’t have to be reduced.
  2. Replace a base with anything congruent to it, especially something small or negative. 99 ≡100 −1 and 50 ≡51 −1 turn huge powers into ±1.
  3. Never reduce an exponent mod n. Reduce it mod p − 1, only when the modulus p is prime and the base isn’t ≡p 0. Otherwise, find the cycle in the powers yourself.
  4. Before you cancel k, check gcd(k, n) = 1. If it is, multiply by k−1, which you get from the Pulverizer. If it isn’t, there are no solutions or gcd-many.
  5. Mod a composite, “product ≡ 0” doesn’t mean a factor is ≡ 0. 3 · 4 ≡12 0, and x2 ≡8 1 has four solutions. Mod a prime, it does.
  6. A congruence mod n gives you one mod every divisor of n, not the reverse. x ≡12 5 ⇒ x ≡4 1, but not ⇐.
  7. For big exponents, use repeated squaring. It takes about 2 log₂ e multiplications of numbers less than n, and works for any modulus.
6

Just for fun: every divisibility test is a fact about powers of 10

Lecture 09’s Theorem 11 (divisible by 9 iff the digit sum is) has a one-line proof: 10 ≡9 1. Every other divisibility trick you’ve heard comes from the same proof with a different congruence for 10 or one of its powers. Here’s the general version, then the rules it produces.

The master rule

Write n with digits d0 (the last one), d1, d2, …. Choose any wi ≡p 10i, ideally a small one.

n = d0 + d1 · 10 + d2 · 102 + ⋯ place value: this is what the digits mean   ≡p d0w0 + d1w1 + d2w2 + ⋯ M5 and M6: replace each 10i with something congruent to it

This replaces the value 10i, not the exponent i, so it’s the substitution §2 allows. Both sides are congruent, so it gives you the remainder, not just whether it’s 0. All the work is in finding good wi, and the powers of 10 mod p always repeat, just like the row of powers in §2.

Try it

Pick a modulus and look at the powers of 10. Find where you hit 1 or −1.

the weights: smallest w ≡ 10i, for i = 0, 1, 2, …

Five rules that come out of it

Each one is the master rule with a pattern in the weights you can remember.

1 · Last k digits  10k ≡ 0

If 10k ≡p 0, every weight from i = k on is 0. Writing L for the last k digits, n = 10kq + L ≡p 0 · q + L = L.
Works for divisors of 10k: 2 and 5 (last digit), 4 and 25 (last two), 8 and 125 (last three). Of the primes from 3 to 23, only 5.

2 · Digit sum  10 ≡ 1

10i ≡ 1i = 1 by Theorem 7 (base substitution), so every weight is 1 and n ≡ d0 + d1 + d2 + ⋯.
Works for divisors of 10 − 1 = 9: that’s 3 and 9. This is Theorem 11.

3 · Alternating digit sum  10 ≡ −1

10i ≡ (−1)i, so n ≡ d0 − d1 + d2 − ⋯, starting from the last digit.
Works for divisors of 10 + 1 = 11. 8645: 5 − 4 + 6 − 8 = −1 ≡11 10, and indeed 8645 rem 11 = 10.

4 · Sum of k-digit blocks  10k ≡ 1

Cut n into k-digit blocks B0, B1, … from the right. Then n = B0 + B1 · 10k + B2 · (10k)2 + ⋯ ≡ B0 + B1 + B2 + ⋯.
Works for divisors of 10k − 1: 99 = 32 · 11, 999 = 33 · 37. 8645 mod 37: 8 + 645 = 653 ≡37 24. And by Fermat, 10p−1 ≡p 1 for every prime p other than 2 and 5, so every such prime has a block-sum test. The blocks can be long, though: 22 digits for 23.

5 · Alternating sum of k-digit blocks  10k ≡ −1

Same blocks, but now (10k)j ≡ (−1)j, so n ≡ B0 − B1 + B2 − ⋯.
Works for divisors of 10k + 1. 1001 = 7 · 11 · 13 gives one test for all three: 8645 → 645 − 8 = 637 = 72 · 13, so 7 | 8645 and 13 | 8645. 10001 = 73 · 137. For 17, 19 and 23 the −1 shows up at k = 8, 9 and 11. Why is it always halfway? If the weights repeat after 2k steps, then (10k)2 ≡p 1, and mod a prime that forces 10k ≡ ±1. That’s the fact from §3, Problem 8, the one that fails mod 8.

The chop rule: multiply by 10−1

A different kind of rule, which keeps only divisibility. Write any number as n = 10a + d, where d is the last digit. For a prime p other than 2 and 5, gcd(10, p) = 1, so 10 has an inverse m mod p. Multiply by it: mn ≡p a + md. Since m is invertible, mn ≡ 0 iff n ≡ 0 (multiply back by 10), so

p | 10a + d  iff  p | a + md.

Cut off the last digit, add m times it to what’s left, and repeat until the number is small. Any m ≡ 10−1 works, so pick the one with the smallest absolute value.

Try it

The chop rule preserves divisibility, not the remainder. Each step multiplies by m, so the new number is ≡ m · (old), not ≡ old. 0 stays 0, which is all a divisibility test needs. The weight-based rules 1–5 are congruences all the way through, so they give you the remainder too. The two kinds agree for 3, because there m = 1. And 5 has no chop rule because 10 has no inverse mod 5. That’s §3 again.
To build a test for any modulus p: list 100, 101, 102, … mod p until something useful appears. If you hit 0, use rule 1. If you hit 1 at 10k, use k-digit block sums. If you hit −1 there, use alternating block sums. Or find 10−1 (Pulverizer, or by inspection) and chop. Every step is M5, M6 or Theorem 7. There’s nothing to memorize.
